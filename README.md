# SPHERE-JEPA

**Official repository for [SPHERE-JEPA: Spherical Prediction with Homogeneous Embeddings](https://arxiv.org/abs/2605.26900).**

Léo Nicollier · Max Dunitz · Marc Pic · Pablo Musé · Enric Meinhardt-Llopis · Gabriele Facciolo

[Paper](https://arxiv.org/pdf/2605.26900) · [Experiment configurations](configs/README.md)

SPHERE-JEPA is a self-supervised learning objective that aligns representations of augmented views while encouraging their normalized embeddings to cover the hypersphere uniformly. Its **Sketched Uniform Spherical Regularization (SUSReg)** matches random one-dimensional projections to a spherical-uniform target. The repository also includes **LeJEPA/SIGReg** as a Gaussian-target comparison. The paper develops the connection between uniform representation geometry and the worst-case behavior of k-nearest neighbors and kernel ridge regression. It reports a 1.8 percentage-point ImageNet-1K linear-probing gain and more than six percentage points of improvement in controlled texture-retrieval mAP; these are results from the paper, not metrics generated by the commands below.

## What is implemented

- SPHERE-JEPA and LeJEPA objectives in [`losses/`](losses/).
- Pretraining on ImageNet-100 (ResNet-18 or ViT-Tiny), Galaxy10 (ResNet-50), and a small MNIST example.
- Texture retrieval with a pretrained DINOv3 ConvNeXt encoder.
- YAML configurations for the supported experiments in [`configs/`](configs/), with the mapping to paper tables in [`configs/README.md`](configs/README.md).
- An online linear probe during pretraining, plus separate frozen-backbone linear-probe and weighted k-NN evaluation. Texture evaluation reports paired-view Recall@1/3/5 and mAP.

The ImageNet-1K ViT-B/14/EMA experiments, ADE20K evaluation, transfer benchmarks, and other baseline objectives from the paper are **not yet implemented in this repository**. See [experiment notes](configs/README.md) for further differences between the current code and the paper's training protocol.

## Installation

The project uses Python 3.12 and [uv](https://docs.astral.sh/uv/). From the repository root:

```bash
uv sync --extra hf
```

`--extra hf` installs the optional Hugging Face `datasets` dependency required by the Galaxy10 and ImageNet-100 loaders. For MNIST or local textures only, `uv sync` is sufficient. `uv` uses the committed `uv.lock` automatically. The DINOv3 ConvNeXt weights are downloaded by `timm` when starting a new retrieval run.

## Quick check: one epoch

`--smoke` runs one epoch with two training batches and small evaluation samples. It checks the complete training, checkpoint, and evaluation path without running the full experiment:

```bash
uv run --extra hf python -m run_pretrained \
  --config configs/imagenet100_resnet18_spherejepa.yaml --smoke

uv run python -m run_retrieval \
  --config configs/texture_wood_spherejepa.yaml \
  --root /path/to/texture/datasets --smoke
```

For **one complete training epoch**, followed by one epoch of the frozen linear probe and k-NN evaluation:

```bash
uv run --extra hf python -m run_pretrained \
  --config configs/imagenet100_resnet18_spherejepa.yaml \
  --epochs 1 --linear-epochs 1
```

On a CUDA machine, add `--devices 1` to select **GPU index 1**, the second visible CUDA GPU. The runner validates that the requested GPU exists. Omit `--devices` for automatic CPU/GPU/MPS selection. `--devices 1` can also be set as `devices: 1` in a YAML file.

## Full experiments

Run a YAML without epoch overrides to use its configured training length:

```bash
uv run --extra hf python -m run_pretrained \
  --config configs/imagenet100_resnet18_spherejepa.yaml

uv run --extra hf python -m run_pretrained \
  --config configs/imagenet100_resnet18_lejepa.yaml

uv run python -m run_retrieval \
  --config configs/texture_wood_spherejepa.yaml \
  --root /path/to/texture/datasets
```

The texture root must contain folders such as `texture_wood/train/all_images/*.png`, `texture_wood/val/all_images/*.png`, and `texture_wood/test/all_images/*.png`. The same layout applies to `texture_disk`, `texture_cloud`, and `texture_flake`. The texture configs contain a local example path; override it with `--root` on another machine. ImageNet-100 can use Hugging Face (`source: hf`) or local class folders (`source: folder`).

To resume a run, pass `--checkpoint /path/to/last.ckpt` with the same config. To evaluate an existing checkpoint without retraining, add `--eval-only`. For example:

```bash
uv run --extra hf python -m run_pretrained \
  --config configs/imagenet100_resnet18_spherejepa.yaml \
  --eval-only \
  --checkpoint outputs/imagenet100_resnet18_spherejepa_seed0/checkpoints/last.ckpt
```

Run artifacts are written under `outputs/<config-name>_seed<seed>/`: `resolved_config.yaml`, `checkpoints/last.ckpt`, and `evaluation.yaml`. Smoke runs use a separate `outputs/smoke_<config-name>_seed<seed>/` directory. The `outputs/` directory is ignored by Git.

## Evaluation protocol

For pretraining, `run_pretrained.py` extracts deterministic **encoder** features from the training and validation splits, and from the test split when available. It trains a separate linear classifier on frozen training features and evaluates weighted cosine k-NN with training features as its reference set. These offline evaluations are distinct from the online probe used during representation learning. `--linear-epochs` controls the offline linear probe; `--skip-eval` skips both offline evaluations.

For textures, `run_retrieval.py` compares two independently augmented views of each test image. The positive match is the other view at the same batch index. Recall and mAP are computed within each evaluation batch, so `batch_size` determines the retrieval candidate set.

The current trainer uses a one-epoch linear warmup followed by a constant learning rate, while the paper describes cosine annealing. The current spherical regularizer also uses a fixed integration limit different from the earlier `Retrieval` implementation. These and the dataset availability notes in [`configs/README.md`](configs/README.md) matter when comparing numerical results with the paper.

## Repository layout

```text
configs/              Experiment YAML files and paper-to-code notes
dataloaders/          MNIST, Galaxy10, ImageNet-100, textures, dataset generator
lightningmodules/     Pretraining and retrieval Lightning modules
losses/               SPHERE-JEPA/SUSReg and LeJEPA/SIGReg
evaluation.py         Frozen linear probe and weighted k-NN
run_pretrained.py      YAML pretraining entry point
run_retrieval.py       YAML texture-retrieval entry point
parameters.py         Default parameter classes
```

Each dataset module has an `if __name__ == "__main__":` block that displays an augmented batch with Matplotlib. For example, `uv run python -m dataloaders.mnist` or `uv run --extra hf python -m dataloaders.imagenet100` opens the corresponding preview.
